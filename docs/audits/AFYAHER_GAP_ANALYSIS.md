# AfyaHer traceable gap analysis

Date: 4 November 2026. Read with the
[current-state audit](AFYAHER_CURRENT_STATE_AUDIT.md), which records fresh test
results and evidence limits. Findings concern existing code/specifications;
no application changes were introduced by this documentation task.

P0 = safety/privacy/critical-correctness release blocker; P1 = MVP functionality;
P2 = important quality improvement; P3 = future enhancement. A P0 marked as a
release blocker does not mean the disabled local prototype is currently giving
live medical answers. No such generator exists. “Missing” is distinct from a
deliberately deferred infrastructure choice.

[draft PRD](../../AfyaHer_PRD.docx) and

## Highest-leverage corrections

1. Close the education API trust-boundary defect and show the actual unavailable
   result. This is testable against the existing stub without medical generation.
2. Reconcile system-design and pilot decisions; establish clinical/privacy owners.
3. Agree immutable source revisions and approval/permission evidence before
   ingesting real content or deciding the database schema.
4. Define reviewed safety/scope and claim-support contracts independently.
5. Repair browser verification and add coverage for the new API path before
   treating the UI as release-ready.

block real-user/public rollout even if that engineering milestone passes.
